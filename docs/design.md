# Astryx 博客视觉规则

本主题以 Astryx 官方 docsite 的 **BlogIndex / BlogArticle** 为视觉来源。当前版式按个人博客的内容重新组织，保留其字体、语义色和真实 Core 控件。主题值由 `src/site-theme.mjs` 转译官方 `astryxTheme.ts`，基础组件通过真正的 Astryx Core 输出。`assets/css/theme.css` 负责博客组合、Hugo Markdown 和少量响应式适配。

这是一套博客主题的实现规则，不是 Hugo 官方规范，也不把 Astryx 文档侧栏或首页营销区移植到博客。

仓库同时提供可直接部署的博客入口。根目录`hugo.toml`保留主题默认值，`blog.toml`独立存放个人配置，`content/`仅包含一篇Hello World和栏目、搜索、归档索引。以`hugo --config hugo.toml,blog.toml`构建，直接使用根模板，不依赖仓库或本地目录名称。主题安装时仅复制可复用组件，不带入博客内容。

首页未设置intro时跟随站点title。作者优先使用显式配置，Pages构建时可从工作流提供的`HUGO_GITHUB_OWNER`取默认值，本地未提供时使用站点标题；单篇author覆盖署名、Article结构化元信息和RSS作者。Pages工作流使用官方元数据提供的baseURL，并仅从默认分支部署。日常内容发布只调用Hugo；重新生成Astryx组件资源由开发者显式执行，测试内容在忽略的work目录生成。

## 主题与色彩

主题名为 `astryx`，从 Core 默认值叠加官方品牌定义，不继承 Neutral 主题。颜色由语义 token 与 `color-scheme` 共同控制，深色模式不另造一套手写色板。

| 语义 | 浅色 | 深色 |
| --- | --- | --- |
| 正文、图标、交互 accent | `#15110C` | `#DFE2E5` |
| body 底层背景 | `#F8F4ED` | `#111112` |
| surface / card | `#FFFFFF` | `#1F1F22` |
| secondary text | `#4E606F` | `#AAAFB5` |
| border | `#05365919` | `#F2F4F619` |
| emphasized border | `#CCD3DB` | `#494D53` |
| on-accent | `#FFFFFF` | `#15110C` |

官方博客的 Core AppShell 使用 **surface**，因此博客页面实际为白色或深灰表面；暖白是 body token，不应把博客内容整体重刷成暖白。

官方品牌蓝 `#225BFF / #3D87FF` 留在品牌 token，不能扩散到按钮、链接、焦点环或正文强调。主题中的站名与作者信息来自配置，不冒用 Astryx 或 Meta 品牌身份。

站点可通过params.astryx.logo指定自己的图片标志。原图留在站点assets中，构建时输出不超过128px的PNG；导航显示32px圆角方形，并与React导航、浏览器图标共用解析后的URL，支持子路径部署。没有配置时保留默认24px Astryx标志。图片不重复提供替代文字，父导航链接由站名命名。

## 字体与字阶

Latin 使用自托管 Figtree Variable，`font-display: swap`；中文交给系统的 CJK 字体回退。字体文件随主题分发，访问页面不依赖第三方字体 CDN。代码使用 Core 的等宽字体栈。

| 用途 | 字号 / 行高 | 字重 |
| --- | --- | --- |
| 列表页主标题 | 32px / 40px | 500 |
| 首页首篇标题，宽度 ≥720px | 32px / 40px | 600 |
| 文章主标题，宽屏 / 手机 | 42px / 52px、32px / 40px | 600 |
| 列表标题，宽屏 / 手机 | 20px / 28px、17px / 24px | 600 |
| 手机首页首篇标题 | 24px / 32px | 600 |
| 普通卡片摘要、页面介绍 | 14px / 20px | 400 |
| 首页首篇摘要，宽度 ≥720px | 17px / 28px | 400 |
| 文章导读，宽屏 / 手机 | 20px / 32px、17px / 28px | 400 |
| 文章正文，中英文相同 | 17px / 28px | 400 |
| 元数据与说明 | 12px / 20px | 400 |
| 控件 label | 14px / 20px | 500 |

`BlogArticle.tsx` 的导读行高值是 `2rem`，根字号 16px 时计算为 **32px**；原文件旁注写 40px，与实际 CSS 值不一致，本主题遵循实际值。

文章语言通过语义 `lang` 标记。中英文采用同一视觉体系，不通过放大中文字号或缩窄英文行宽另建阅读风格。极长英文词和 URL 允许折行；代码块、表格使用局部横向滚动。

## 页面构成

Core Section 的**外框最大宽度为 800px**，内边距为 24px。内层 `.blog-index` 和 `.blog-article` 不再次加内边距。正常宽屏的有效内容宽度为 752px；375px 与 390px 手机的内容宽度分别为 327px、342px。

主内容顶部内边距为32px，Section保留24px内边距。Header内层也限制为800px、内边距24px，让品牌、正文、日期栏与页尾共用对齐线。沿用80% surface、12px模糊的背景，不改变Core TopNav的按钮和导航样式。

手机导航采用本项目的博客适配：从顶部按钮打开真正的 Core Popover，宽度上限288px，内容为紧凑导航与 RSS，不使用全高侧抽屉、重复品牌头部或全屏遮罩。打开、关闭、键盘循环与焦点恢复由 Core 负责；跨过768px断点时主动关闭。手机顶栏的三个图标控件至少40px，站名可截断，RSS进入菜单。弹出采用 Core 的轻微入口动效，并遵循减少动态效果偏好。

原生 Hugo 控件的焦点样式在 `reset` 层以零权重 `:where()` 提供回退，Core 控件保留自己的轮廓及抑制规则。仅降低选择器权重不足以解决覆盖：未分层的 CSS 总是优先于 Core 的 `astryx-base` 层。主题不能给自动聚焦的面板或 CommandPalette 内嵌输入重新画矩形边框。颜色模式切换时 Header 表面立即与页面同步，不单独延迟300ms重绘。

列表页采用安静的文章索引：标题保持左对齐，首页的最新文章说明和小号 Core 类型筛选放在同一条工具行，不将筛选居中作为视觉主角，也不重复显示文章计数。分类能力与无JavaScript的锚点导航保留。

首页页头在720px以上将站名与现有简介分置两侧，简介最多18rem，底部基线对齐；窄屏自然堆叠。文字保留正常换行，极长单词可折行。页头到文章区的间距为宽屏64px、窄屏48px，通过构图与留白建立层级，不增加口号或装饰图形。

文字文章按日期排列在单列索引中。宽屏使用76px日期栏、24px列间距和正文栏；真实配图的普通条目增加152px缩略图。日期使用等宽数字，文章之间以语义色细线和28px上下留白区分，不给每条文章增加盒子、阴影或背景。640px以下日期回到标题上方，真实图片放在文字之后。摄影列表仍使用大幅、原比例图片，避免把不同内容都套进同样的卡片。

640px以上日期与标题首行通过CSS baseline对齐，首页首篇和普通文章都使用实际字体基线，不用固定上边距猜测位置。摄影缩略图仍靠顶部排列。

首页首篇保留适度的字号与摘要层级，取消自动大面积装饰封面。未提供配图的文章不生成图案；真实配图保持16:9、16px圆角及Core AspectRatio。需要原官网装饰封面时，可显式设置coverFallback="art"或单篇coverArt=true，单篇false关闭图案回退，真实cover始终优先。不靠无关的装饰填满版面。

列表不重复显示站点作者，作者信息留在文章页。索引只保留类别、阅读时间和必要的语言标记，用次要颜色的分隔点区分；每个分隔点与后续文字一起换行，辅助技术不朗读装饰符号。按类型筛选后首篇也恢复普通条目的密度。悬停和键盘焦点以标题的1px细下划线提示链接，摘要与元信息保持次要颜色，封面保留轻微罩层。下划线颜色使用border-emphasized并短暂过渡，减少动态效果时取消过渡。

文章头部的面包屑、标题、导读、作者日期与分隔线之间为16px。作者使用14px/20px、500字重的主文字色，日期与阅读时间保留12px supporting字阶，以不朗读的分隔点组合并换行。日期使用等宽数字。头部、封面、正文、页尾之间为40px。

文章导读及正文的段落、标题、列表、引用和脚注统一限制为42rem（672px），所有语言使用同一规则，左边缘与页面对齐；图片、代码和表格保留752px外框空间。正文段距为16px，一级、二级标题上下留白40px/16px，三级标题保留24px/12px，四级及以下沿用Core默认密度；首尾元素不额外增加外边距。正文链接的1px下划线在静止时采用secondary文字色，悬停或键盘焦点时采用主文字色。图片保留原始比例，图注使用supporting字阶；文章封面按博客封面比例裁剪。

摄影、研究、归档、标签和搜索沿用相同的外框、语义颜色与组件。摄影列表保留图片比例；当前分页只有一篇时图片铺满752px内容宽度，多篇保留原网格。摄影说明使用body字阶，日期使用supporting，图片sizes对应实际单列与双列宽度。

归档用年份分组和日期栏呈现，整行由Core Link提供，点击高度至少40px；标题在宽屏为14px/20px，手机为17px/24px，日期使用等宽数字。标签页采用双列、手机单列的整行Core链接，名称14px、数量12px，最小44px高度，以细线区分。Hugo自动生成的标签页标题随界面语言翻译，显式内容文件的自定义标题优先保留。

页脚为适合个人博客的精简导航，沿用官方 supporting 字阶、分隔线与中性色；有标签时提供标签索引入口。分页使用真实Core Button链接，保留当前页语义及前后页关系，最小40px点击范围。

文章结束处使用没有背景盒子的Core文字链接，方向图标和supporting说明位于文章标题之前。宽屏前后篇分别靠左、靠右；手机按顺序靠左排列。英文文章主标题与首页首篇使用渐进增强的均衡换行；中文标题及正文保留自然段落流动。

文章索引、前后篇、归档、标签、摄影说明和独立搜索结果共用1px细下划线反馈，仅过渡颜色；键盘焦点与触摸按下同样可见。页脚与搜索弹窗链接使用同一快节奏token。减少动态效果时取消这些过渡，不加入页面位移、滚动入场或连锁动画。

## 组件与内容适配

导航、按钮、筛选、表单、主标题、文本、面包屑、标签等低层 UI 使用真正的 Core 组件输出。不得只加 `.astryx-*` 类名伪装组件，也不在 CSS 中重画这些组件。

CSS调整博客组合与必要的局部字号。当前安静索引和手机字阶是此次用户反馈要求的版式适配，不冒充官网原版几何；颜色、字体、组件和基础圆角仍遵循官方来源。生成组件包裹在 Hugo 的高层类名中时，标题、摘要和导读的子元素继承组合层的官方字号，避免包裹层与 Core 元素出现两套字号。

目录是 Hugo 长文适配，官方 BlogArticle 没有目录。主题使用原生 `details`，默认收起，放在文章头部的分隔线之后；没有侧栏或新的 React 目录交互。摘要整行至少40px，使用真正的Core chevron标明开合，箭头轻微旋转并遵循减少动态效果偏好；目录条目至少32px，触摸设备40px。无 JavaScript 时仍可直接展开并阅读。全站showToc支持显式false，单篇showToc可覆盖全站默认值。

触摸设备的面包屑链接也保留至少40px点击区域。生成Core模板时优先替换较长占位符，避免SLOT_TEXT误伤SLOT_TEXT_LANG而破坏真实语言声明。

连续长目录标题与图注可在任意必要位置折行。文章标签的列表、外链与Core Badge限制在内容宽度内，Badge沿用自身省略与title属性保留完整标签。检查这些边界必须测量元素自身和父区域，不能仅检查文档总宽度；AppShell的裁剪会隐藏超宽子元素。

正文由 Hugo 生成，使用对应 Core Markdown 的语义值。正文链接保留下划线。脚注、表格、引用、嵌套列表、长代码、图注和翻译链接属于正式支持内容，不通过删减示例避开边界问题。Chroma 语法类别映射到 Astryx syntax token，深色模式自动跟随主题。

代码块在构建时生成语言与可选文件名工具栏，Hugo Chroma 输出语法类别、可选行号及指定行高亮。复制使用工具栏中的 Core Button，位于滚动区外；复制源保存在转义后的 JSON 属性中，不混入行号、标签和搜索正文。未知语言使用纯文本渲染，无 JavaScript 时保留工具栏与完整代码。实际溢出的代码和表格可通过键盘聚焦并滚动，未溢出时不增加额外 Tab 停靠。滚动区尚有内容的一侧使用20px柔和渐隐，滚到尽头即消失；代码提示从实际工具栏下方开始，不能遮住语言、文件名或复制控件。窗口尺寸和字体就绪后重新判断溢出。目录锚点仅使用文档的72px滚动间距，避免与标题的 scroll-margin 重复叠加；只为读者主动点击的正文锚点平滑滚动，减少动态效果时立即定位。全局滚动保持auto，Core滚动锁释放和浏览器历史恢复不得产生从页首滑回原位置的动效。手机搜索弹窗输入使用16px字号。

脚注回链显示“返回正文”或“Back to text”，手机扩大数字引用的点击范围，保持上标位置与正文行流。脚注及回链点击时短暂使用accent-muted提示目标；标题和脚注目标临时可聚焦，失焦后移除临时属性。历史前后返回仅恢复对应锚点的键盘起点，滚动交给浏览器，修饰键、新窗口与原生无JavaScript导航继续保留。

复制按钮按所有反馈文案的实际字体宽度预留空间，成功、失败时不挤动语言和文件名；结果由polite状态区播报，权限失败明确说明手动复制。语言与文件名在窄屏内省略，并以title保留完整内容；语言不得强制不收缩而挤出按钮。

图片链接在聚焦或指针进入时预加载真实Core Lightbox。首次加载超过120ms时显示Core Dialog反馈，加载失败保留重试、关闭和原图入口；短等待阶段的Escape同样有效。异步模块错误限制在图片预览内部，不卸载导航和其他增强控件。独立图片模块由Hugo生成指纹URL，失败重试使用新查询参数绕过浏览器失败模块缓存，路径随子目录部署。关闭后的加载结果不得重开预览，最终焦点回到原图链接且不改变阅读滚动位置。背景模块预加载失败后不因焦点返回重复请求，等待明确打开或重试。图库按原图URL去重，保留点击来源作为关闭后的焦点位置，并从重复正文图片补全图注。原图加载失败时使用同一Core Dialog反馈，可重试、打开原图或继续浏览其他照片；显式重试进行图片解码，并在20秒后恢复可重试的错误状态。关闭或换图取消当前重试，迟到结果不能覆盖现有会话。

搜索使用真正的 Core CommandPalette、输入槽与公开上下文，在同一套组件上组合文章检索界面。输入栏使用16px字号，关闭控件至少40px；最近发布/结果数量作为次要信息。结果行不叠加两层内边距，标题最多两行、摘要一行，语言与日期使用12px字阶。关键词安全地渲染为文字标记，不插入查询HTML。手机省略快捷键提示，弹窗高度跟随可见视口，保留关闭按钮及完整索引入口；输入关键词后入口显示“全部结果”，携带当前关键词进入独立搜索页。独立搜索页使用同样的紧凑文章列表，150ms输入停顿后即时过滤，中文组合输入完成后才搜索。清空立即恢复原始静态顺序，不等待索引；关键词同步URL并保留现有history.state、其他参数和片段，历史返回时恢复输入与结果。状态区播报加载、数量、空结果及错误，旧请求不得覆盖更新后的查询。索引失败时恢复全部文章与可用链接，后续输入或提交可重试；JavaScript失败时仍可浏览全部条目。

评论由 Hugo 全站配置和单篇布尔开关决定是否输出。未开启或缺少后端配置时不显示空壳。主题实现评论标题、GitHub入口、手动/延迟加载与错误重试，按钮由 Core SSR生成。giscus负责GitHub认证与评论数据； iframe内部通过独立的浅/深色CSS适配Figtree、官网中性色、16px表面圆角和胶囊按钮，使用官方setConfig消息同步外观。跨域CSS与字体的CORS要求在部署说明中明确记录，不依赖父页面样式穿透iframe。

手动加载评论期间保留可见的发起按钮和焦点，用aria-disabled与请求状态防止重复加载；失败后可原位重试。评论就绪时，只有手动发起且仍聚焦在该按钮的用户才转入iframe；自动加载与已移开的阅读焦点不被打断。

CLI 生成的 reset 会直接给原生 `p` 设置全站 body 字阶，因此 `.prose p` 必须继承正文容器的字号、行高和颜色；否则实际段落会退回 14px / 20px，引用里的段落也会失去 secondary 颜色。Core reset 同时清除列表标记，Hugo 正文需显式恢复圆点与序号。

## 验收约束

- 375px、390px 和常见桌面宽度均无页面横向溢出；代码与表格溢出只在本地滚动。
- 核实真实计算样式、Figtree 加载与 Core 组件来源，不仅对照截图。
- 核实首页、中文文章、英文文章、深色模式、搜索与摄影列表。
- JavaScript 未加载时导航、文章链接、分页、目录和完整内容仍可使用。
- `[hidden]` 必须隐藏，被 flex 或 grid 布局覆盖不能让筛选结果重新出现。
- 键盘焦点清晰可见；搜索结果状态可被辅助技术读取。
- 减少动态效果偏好关闭页面层过渡；打印隐藏导航与交互控件。
- 不加入营销 hero、bento、宣传口号、虚构指标、装饰性色块或另造字体体系。

后续改动应先判断它是内容适配还是改变官网视觉基线。调整基线需要明确更新本文件中的对应指标与来源，不能继续向另一套独立审美漂移。
